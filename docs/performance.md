# 0.2.0 성능 검증 기록

검증일: **2026-10-11 UTC / 2026-10-12 한국시간(UTC+09:00)**. 이 기록은 `0.2.0` 변경의 검증 결과와 적용 범위를 설명합니다. 수치 요약은 [performance.json](performance.json)에 있으며, 실제 대학의 통계 관측값이나 보고서 세션 정보는 포함하지 않습니다.

**합성 표의 파싱 중앙값은 기본 출력에서 약 11.70배, 불필요한 XML 트리를 생략하는 경로에서 약 15.57배 빨라졌습니다.** 이는 로컬 파서만 측정한 결과입니다. 공식 서버 대기나 LLM의 답변 시간을 포함한 전체 조회 속도의 배수가 아닙니다. 실제 원천 조회에서는 여전히 서버 통신·보고서 초기화·생성 확인 시간이 대부분을 차지했습니다.

## 비교 기준과 검증 범위

비교 기준은 설치된 `academyinfo-flow 0.1.0`을 가져온 다음 커밋입니다.

```text
9ac44cbba4fbf7f919466c2c21ee566dd0cc738d
Import installed academyinfo-flow 0.1.0 source
```

현재 파서와 기준 파서를 동일한 합성 XML에 적용했습니다. [차등 검증·벤치마크 스크립트](../tests/parser_benchmark.py)는 정상 표와 오류·모호성 사례의 반환 결과를 비교하고, 별도의 합성 표에서 실행시간을 측정합니다. [합성 자료 생성기](../tests/parser_fixtures.py)는 실제 대학의 통계값을 사용하지 않습니다.

| 검증 항목 | 결과 | 의미 |
| --- | --- | --- |
| 차등 검증 | 48개 사례 통과 | 정상 출력과 오류 판정이 비교 기준과 일치했습니다. |
| 기본 파서 출력 | JSON 바이트 일치 | 값뿐 아니라 직렬화 순서까지 같은 결과를 확인했습니다. |
| XML 트리 생략 경로 | 보존 대상 의미·검증 결과 일치 | 기존 결과에서 원시 XML 트리만 제거한 결과와 비교했습니다. |
| 최종 전체 단위 테스트 | 66개 통과, 0.726초 | 보고서 20개·일괄 조회 15개·지침 13개·파서 18개입니다. |
| 스킬 구조 검증 | 유효 | `quick_validate` 검사에 통과했습니다. |

차등 검증은 [파서 테스트](../tests/test_report_tables.py), [보고서 조회 테스트](../tests/test_live_report.py), [일괄 조회 테스트](../tests/test_live_batch.py), [지침 조회 테스트](../tests/test_live_guide.py)를 보완합니다. 합성 자료에서 통과했다는 사실만으로 모든 실제 장표의 해석이 검증됐다고 보지는 않습니다.

## 1. 로컬 표 복원 시간

측정 표는 **60행 × 24열**, XML 크기는 **152,873바이트**입니다. 각 경로를 **3회** 실행한 중앙값을 비교했습니다. 네트워크 요청, PDF 수신, LLM 처리와 최종 JSON 출력 시간은 이 측정에 포함되지 않습니다.

| 파서 경로 | 중앙값(초) | 기준 대비 속도 |
| --- | ---: | ---: |
| 0.1.0 기준 파서 | 0.243366 | 1.00배 |
| 최적화 파서, 기존 기본 출력 | 0.020805 | 11.70배 |
| 최적화 파서, 원시 XML 트리 생략 | 0.015627 | 15.57배 |

주요 변경은 같은 셀의 Decimal 좌표를 반복 계산하지 않도록 한 것, 각 행에서 관련 셀만 확인하도록 탐색 범위를 줄인 것, 라이브 조회에서 곧바로 버리던 원시 XML 트리를 처음부터 만들지 않는 것입니다. 기본 파서 출력 형식과 페이지·표 구조의 오류 검증은 유지합니다.

측정은 하나의 실행 환경과 합성 표에서 얻은 기술적 관측값입니다. 세 번의 실행으로 다양한 하드웨어·장표 크기·서버 상태에 대한 성능 분포를 추정하지 않습니다. 속도 배수를 테스트 합격 조건으로 두지 않으며, 재실행 값은 달라질 수 있습니다.

## 2. 간결한 출력의 크기

실제 `live_report` 반환 경로에 **합성 20행**을 적용한 비교에서 JSON 크기는 다음과 같았습니다. 실제 대학의 조회 결과를 보존하거나 통계 행을 게시한 측정은 아닙니다.

| 출력 방식 | JSON 크기 |
| --- | ---: |
| 전체 출력 | 33,102바이트 |
| 간결한 출력 | 15,105바이트 |
| 감소량 | 17,997바이트, 약 54.37% |

측정은 [보고서 테스트](../tests/test_live_report.py)의 `LiveReportTests`를 준비해 `run_report()` 결과와 `compact_result()` 결과를 각각 `json.dumps(ensure_ascii=False)`의 기본 옵션으로 UTF-8 직렬화했습니다. 실행시간 필드의 문자열 길이에 따라 재실행 크기는 조금 달라질 수 있습니다.

간결한 출력은 중복되는 `keys`, `cells`, `cell_sources`를 생략합니다. 원천 값, 문자열·빈값·null·대시의 구분, 학교·학과 차원, 열 정의, 원천 페이지·해시·출처, 오류·경고·완전성은 유지합니다. 같은 비율이 모든 장표에서 나온다고 가정하지 않습니다.

`live_batch.py`는 기본으로 간결한 출력을 사용하며 `--full-output`으로 전체 출력을 요청할 수 있습니다. `live_report.py report`의 기존 출력은 기본적으로 유지하고 `--compact`를 지정했을 때 간결하게 반환합니다. 선택조건과 출력 규칙은 [일괄 조회 명세](../skills/academyinfo-flow/references/performance.md)를 참조하세요.

## 3. 공식 서버 연결 확인

[대학알리미 공식 서버](https://www.academyinfo.go.kr/)에 실제로 접속하여 공개 범위·공시목록과 제한된 장표 조회를 확인했습니다. 아래 시간은 한 차례 실행의 관측값이며 서버 응답시간의 평균이나 보장값이 아닙니다.

| 확인 항목 | 관측 결과 | 시간 |
| --- | --- | ---: |
| `scope` | 정상 완료, 최신 공개 연도 `2026` 확인 | 8.672초 |
| `catalog` | `2026`년 항목 ID `31`, `4-마. 재적 학생 현황` 확인 | 8.706초 |
| 장표의 첫 번째 반환 범위 | 원천 보고서를 새로 조회한 부분 결과 | 40.063501초 |
| 같은 배치의 두 번째 반환 범위 | 같은 실행에서 받은 장표를 다른 범위로 투영 | 0.001999초 |

`scope`와 `catalog`는 실행 경과시간이고, 장표의 개별 시간은 `run_command` 시작부터 결과 검증까지의 내부 계측입니다. 장표 배치 전체 내부 시간은 **40.067035초**, 외부에서 관측한 실행시간은 **40.143초**였습니다. 내부 시간에는 최종 JSON 직렬화·전달 이후의 LLM 처리시간이 포함되지 않습니다.

### 이 확인은 전체 통계 조회가 아닙니다

실제 장표는 공식 생성 상태상 **13페이지**였고, 네트워크 동작 확인을 위해 의도적으로 **1페이지만** 받았습니다. 각 반환은 `limit=1`이며 `offset=0`, `offset=1` 두 범위를 요청했습니다.

| 확인 항목 | 첫 번째 범위 | 두 번째 범위 |
| --- | --- | --- |
| 반환 상태 | `partial` | `partial` |
| `complete` | `false` | `false` |
| 원천 전체 페이지 수 | 13 | 같은 원천의 13 |
| 해당 호출에서 새로 받은 보고서 페이지 | 1 | 0 |
| `source_complete` | `false` | `false` |
| `returned_complete` | `false` | `false` |
| `table_validation_complete` | `false` | `false` |
| `source_reused` | `false` | `true` |

첫 번째 조회에서 확인하지 못한 페이지와 표 검증 상태가 재사용 결과에서도 그대로 유지됐습니다. 이를 완전한 재적 학생 통계, 전체 학교 집계, 누락 없는 순위로 해석할 수 없습니다. 이번 확인으로 검증한 것은 공식 원천 연결, 같은 배치의 장표 재사용, 반환 범위 변경, 부분 결과 상태의 보존입니다.

배치에서 기록한 `source_report_fetches=1`은 **논리적인 장표 원천 실행이 한 번**이라는 뜻입니다. 단일 HTTP 요청이라는 뜻이 아닙니다. 장표 한 번에도 공시목록 조회, 보고서 초기화, 생성 상태 확인, 페이지 수신과 최종 상태 확인 등의 HTTP 요청이 필요합니다. `repeated_report_sources_avoided=1`도 이 원천 실행의 중복을 한 번 줄였다는 의미입니다.

### 남아 있는 원천 대기시간

첫 번째 실제 장표 조회의 주요 단계는 다음과 같았습니다.

| 단계 | 내부 시간(초) |
| --- | ---: |
| 공식 공시목록 조회 | 9.943182 |
| 보고서 초기화 | 17.361141 |
| 생성 완료 확인 | 6.568357 |
| 최종 상태 확인 | 6.169868 |
| 수신한 표의 파싱 | 0.015164 |

이 실행에서는 파싱보다 공식 서버와의 통신·보고서 준비를 기다리는 시간이 훨씬 컸습니다. 로컬 표 복원을 최적화해도 첫 조회의 이 대기시간은 남습니다. 반면 같은 질문에서 다른 학교나 반환 범위를 따로 읽는 중복 원천 실행은 배치 안에서 줄일 수 있습니다.

## 4. 유지한 동작과 적용 한계

- **새 실행은 새 원천 조회입니다.** 같은 `live_batch.py` 실행 안에서만 갓 받은 장표·동일 JSON 조회 결과를 재사용합니다. 종료 시 재사용 자료를 폐기하고 다음 실행에서는 공식 서버를 다시 조회합니다.
- **장표 출처가 달라지면 별도로 조회합니다.** 연도·기관 구분·항목·조회 단위·페이지 제한 등이 다른 장표를 같은 원천 결과로 취급하지 않습니다.
- **학교 필터를 서버에 새로 구현하지 않았습니다.** 일반 장표는 공식 보고서의 수신 결과에서 학교·학과 차원을 필터링하는 구조입니다. 여러 학교를 요청해도 원천 서버에서 해당 학교 행만 바로 받는다고 설명하지 않습니다.
- **요청 간격과 순차 수신을 유지합니다.** 무제한 병렬 호출이나 원천의 접근 제한 우회를 추가하지 않았습니다. 페이지 제한을 줄이면 더 작은 부분 결과가 될 뿐 전체 통계 조회가 빨라졌다고 볼 수 없습니다.
- **출력의 크기 감소와 LLM 시간 감소는 같은 측정이 아닙니다.** JSON 바이트 감소는 확인했지만 모델별 토큰 수나 답변 완료시간은 별도로 측정하지 않았습니다.
- **측정 기록은 통계 아카이브가 아닙니다.** 이 문서와 JSON은 합성 자료의 크기·시간, 상태·완전성·조회 범위 같은 확인 요약만 보존합니다. 실제 통계 관측 행, 응답 원문, 보고서 임시 키, 쿠키, 인증정보는 포함하지 않습니다.

## 5. 재현 방법

저장소 루트에서 실행합니다. 아래 절차는 단위 테스트와 합성 파서 비교, 패키지 생성이며 공식 서버에 전수 조회를 요청하지 않습니다. 기존 작업 경로와 겹치지 않는 별도의 기준 버전 경로를 사용하세요.

```bash
git worktree add --detach ../stoom-acaflow-baseline 9ac44cbba4fbf7f919466c2c21ee566dd0cc738d
python -m unittest discover -s tests -v
python tests/parser_benchmark.py --baseline ../stoom-acaflow-baseline --rows 60 --columns 24 --repeats 3
python scripts/build_plugin.py
```

이미 기준 버전을 다른 곳에 받은 경우에는 다음처럼 경로를 전달할 수 있습니다.

```bash
python tests/parser_benchmark.py --baseline /path/to/previous-release --rows 60 --columns 24 --repeats 3
```

벤치마크는 비교 기준 저장소·스킬 디렉터리 또는 `report_tables.py` 파일을 받을 수 있습니다. 기본 출력과 오류 판정이 달라지면 시간 비교를 통과시키지 않습니다. `include_raw_tree=False` 경로도 기준 결과에서 원시 트리만 제거한 결과와 비교합니다.

패키지 생성 명령은 현재 매니페스트의 버전으로 `dist/academyinfo-flow-0.2.0.zip`을 만듭니다. 공식 매니페스트와 호환 매니페스트의 이름·버전·기본 프롬프트 일치를 확인하고, 스킬 소스만 묶으며 테스트·문서·실행 캐시는 포함하지 않습니다. 패키지 생성 자체가 설치 또는 공개 배포를 수행하지는 않습니다.

실제 서버 속도를 재측정할 때는 먼저 `scope`와 `catalog`로 현재 공개 연도와 항목을 확인하고, 질문에 필요한 제한된 범위만 요청하세요. 이번의 항목 ID·페이지 수·시간을 미래의 원천 상태로 가정하지 않으며, 제한된 수신 결과는 계속 `partial`로 다룹니다.
