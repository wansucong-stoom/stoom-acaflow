# 장표 복구와 조회 제한

장표 응답이 실패하거나 일부만 반환됐을 때 읽는다. 같은 요청의 성공한 scope·catalog·원천 JSON은 재사용한다. 실패한 원천 조회를 성공으로 표시하거나 이전 수치로 메우지 않는다.

## 초기화 시간 초과

- `error.code=source_timeout`, `error.stage=report_initialize`이면 이번 시도의 공식 표 초기화가 시간 안에 끝나지 않은 것이다. HTTP 200인 앞 단계가 있어도 장표 조회 성공은 아니다. 커넥터가 실제 호출되어 구조화된 원천 오류를 반환한 사실과 표 초기화 실패를 구분한다.
- 요청 연도·기관·항목·조회 단위가 이번 공식 목록과 맞고 접근 거부나 미지원이 확인되지 않았다면 같은 조건으로 **새 조회를 한 번만 추가 시도**한다. 재시도는 별도 시도이며 최초 실패의 시각·상태를 보존한다. 두 번째 실패 뒤 자동 반복하지 않는다. 호스트가 재시도를 막으면 그 상태를 보고한다.
- `limit`·학교 필터를 줄여도 전국 표 초기화가 가벼워진다고 가정하지 않는다. 클라이언트가 허용하지 않는 timeout 인자를 만들지 않는다. 개별 요청 시간·전체 시간·최대 원천 요청 수는 현재 schema와 응답 `resource_bounds`에서 확인한다. 전체 예산을 넘도록 무한 대기하거나 재시도하지 않는다.
- `query_deadline_exceeded`는 전체 요청 시간 한도 도달이며 개별 원천 요청의 `source_timeout`과 다르다. 같은 조건의 초기화 재시도 대상으로 자동 분류하지 않는다. 확보 범위와 실패 단계를 확인하고 예산 안에 완료할 수 있는 공식 경로가 있는지 검토한다.
- 재시도도 실패하면 지원되는 공식 파일·웹·Python 경로로 요청 범위를 새로 확보할 수 있는지 확인한다. 도구가 없거나 같은 제한 때문에 진전이 없으면 현재 한계를 보고한다. 대체 경로가 성공할 것이라고 약속하거나 사용자가 지정하지 않은 보존본으로 새 수치를 대신하지 않는다.

## 페이지 제한과 반환 제한

전국 장표의 총 페이지 수가 일반 report 한도를 넘으면 [대용량 이어받기](large-reports.md)의 start·continue·read 경로를 사용한다. continue의 호출당 페이지 한도를 전체 상한으로 오해하지 않는다.

`completeness.source_complete`는 전체 원천 페이지 수신·검증, `completeness.returned_complete`는 필터에 맞는 전체 행 반환 여부다. 최상위 `complete`·검증 상태·경고도 함께 읽는다.

전국 합계처럼 전체 행이 필요한 요청은 첫 조회부터 전체 범위에 맞춰 계획한다. 전체 페이지 수가 미확인이고 사용자 상한이 없다면 현재 report schema의 최대 `max_pages`를 명시한다. 전체 페이지 수가 확인됐다면 필요한 수를 허용 상한 안에서 사용한다. 이 선택은 요청에 필요한 전국 장표의 조회이며 다른 항목의 전수 수집으로 확대하지 않는다. 페이지 수를 크게 요청해도 시간·바이트·요청 수 예산과 모든 검증은 그대로 적용된다.

| 실제 상태 | 다음 행동 |
| --- | --- |
| `max_pages`에 도달해 예상 페이지보다 적게 수신 | 같은 조건을 반복하지 않는다. 실제 도구 상한 안에서 전체 페이지를 받을 수 있으면 필요한 범위로 조정한 새 조회를 한 번 수행한다. 예상 전체가 상한을 넘으면 현재 경로만으로 전국 합계를 확정하지 않는다. |
| 원천은 완전하지만 `limit`·`offset` 때문에 반환만 제한 | 이미 확보한 전체 JSON을 읽거나 도구가 제공하는 같은 자료의 반환 기능을 사용한다. 출력 범위 상태만으로 원천 장애라고 판단하지 않는다. 새 report 호출이 원천을 다시 조회하는 도구라면 시점 차이를 남기고 서로 다른 시도의 행을 무검증으로 합치지 않는다. |
| 반복 페이지·표 정체성 불일치·생성 페이지 수 변경·해석 미지원 | 페이지 수가 맞아도 완료로 표시하지 않는다. 경고와 검증 실패를 확인하고 확보 범위만 보고한다. |

`limit`는 반환 행 범위이고 `max_pages`는 수신 페이지 제한이다. schema가 더 큰 값을 받더라도 실제 서버 상한이 이를 제한할 수 있다. `resource_bounds`가 없으면 현재 도구 schema와 실제 반환의 제한 사유를 근거로 판단하고 상한을 추측하지 않는다.

## 실패·부분 결과 보고

실패 단계와 조회 조건의 사람이 읽을 수 있는 이름, 반환 행 수, 확인된 수신/예상 페이지 수, 전체 여부와 남은 범위를 짧게 알린다. 총 페이지 수를 확인하지 못했다면 미확인으로 표시한다. 빈 행·실패는 0이 아니며, 부분 자료로 전국 합계·누락 없는 순위를 내지 않는다. 재시도 성공 시 성공 시도의 출처·조회 시각을 사용하고 앞선 실패와 구분한다.
