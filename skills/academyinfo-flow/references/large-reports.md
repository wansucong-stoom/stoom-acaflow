# 전국 대용량 장표 이어받기

MCP 서버 0.2.6에서 제공한다. 실제 tool schema가 우선이며 스킬 ZIP만으로 서버 기능이 생기지 않는다.

1. 이번 scope·catalog에서 공개 연도·기관·항목 ID와 학과 지원을 확인한다.
2. 전국 장표는 `academyinfo_report_start(year, division, item, level="department")`로 한 번 초기화한다. 학교·학과 필터를 임의로 걸어 전국 범위를 좁히지 않는다.
3. 응답 `job_id`, `next_page`, `job_status`, `expected_pages`를 읽고, `academyinfo_report_continue(job_id, expected_next_page=next_page, max_pages=64)`를 반복한다. 생성 중이면 같은 job으로 상태를 이어 확인한다. `retry_after_seconds`가 있으면 그 시간 후 같은 job을 사용한다. 같은 호출 안에서 상태 확인·페이지 수신·진행 저장은 한정된 시간·요청·바이트 예산을 따른다.
4. 일시적인 빈 응답·timeout·HTTP 500/502/503/504는 확보한 페이지를 유지하고 같은 실패 페이지에서 최대 두 번 추가 시도한다. `job_status=failed`이면 자동 반복하지 않는다. 접근 거부·DTD·표 불일치·반복 페이지·생성 수 변경은 완료가 아니다.
5. 모든 페이지와 최종 생성 수·열 구조·본문·중복 검증이 끝나야 `job_status=complete`다. 진행 요약은 데이터 행 전체가 아니다. `download_url`의 전체 JSON(`columns`, `pages[].rows`)을 받거나 `academyinfo_report_read`를 `start_page`/`read_next_page`로 끝까지 읽는다. read는 원천을 재조회하지 않으며 새 조회 시각으로 바꾸지 않는다. read 부분만으로 전국 합계·순위를 계산하지 않는다.
6. 페이지 수신은 전체 5,000쪽, 호출당 최대 64쪽으로 제한한다. 사용자 요청의 항목만 처리하며 다른 항목 자동 수집으로 확대하지 않는다. 원천 서버 장애·세션 만료·미지원 표까지 무오류를 보장하지 않는다.

새 조회의 원천 세션·쿠키는 모델 출력·다운로드에 노출하지 않고 서버의 비공개 전용 저장 경로에 임시 보관한다. 원문 XML은 저장하지 않으며 검증한 공개 행과 페이지 근거만 같은 작업에 보존한다. 작업은 생성 후 2시간에 접근 만료된다. 완료·실패 시 원천 연결 상태를 제거한다. 만료 접근과 새 작업의 제한된 정리에서 임시 파일을 삭제하며, 즉시 삭제하려면 `academyinfo_report_cancel(job_id)`을 사용한다. 만료 시각의 즉시 물리 삭제를 뜻하지 않는다. 규정 아카이브·학생 DB를 수정하거나 과거 관측값으로 새 조회를 대신하지 않는다.

한 대학 학과 조회는 `academyinfo_report`에 정확한 학교명 하나를 사용하면 공식 명부 검증 뒤 학교 상세 양식 60으로 자동 이동한다. 학교 상세에서 합계·대학원·이전 소속 행을 학교코드로 덮어쓰지 않는다. 전체 열 경로·기준기간·지침 단위와 산식은 별도로 확인한다.

서버 0.2.6은 continue 호출에만 원천 요청 최대 72회·최대 64쪽 예산을 사용합니다. 일반 report는 최대 32쪽·40회 예산을 유지합니다. 저장소 지연·원천 속도에 따라 한 호출이 최대보다 적게 받아도 동일 next_page로 계속합니다.
